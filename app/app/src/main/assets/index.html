接线诊断—
双通道持续接线：① SO 数据变化即把 /summary 以 POST /data 推到 18767；② 本机后台持续监控，一旦推送静默超过 20 秒（大于 SO 的 15 秒兜底心跳，避免把降频后的全量读拉回高频）就主动向 18765 拉 /summary 兜底。18767 只接收/拉取、绝不往外推。冷启动还会从 frames.jsonl 读回上次会话末帧（标注「归档」）。缺值一律显式 −1，「没有」和「是 0」长得不一样。

链路 SO → 18767

游戏进程内 libhachimi_ura.so 在 18765 起 HTTP，

两条通道都把 /summary 归一化成育成属性帧，同源提供本面板。

两条链路 别弄混

本 App 走 手机线：SO 在 18765 提供 HTTP（本机后台持续主动拉），并主动 POST /data 把 /summary 推到本机 18767 收；18767 只收不推。
电脑版 URA 是另一条独立链路：Hachimi-Edge V3 把原始 MessagePack 以 POST /notify/response 送到 127.0.0.1:4693，由 FestaScenarioAnalyzer / SendGameStatusPlugin / AIRedirector 解析与喂 AI。
